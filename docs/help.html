JV Measurement Software — User Documentation

Version 2.6.0 | Open-source characterization tool for perovskite solar cells

Developed by Lucas Polimante — Universidade Federal do ABC (UFABC)

1. Overview

JV Measurement Software is an open-source Python application for automated characterisation of perovskite and other thin-film solar cells, built for use with a Keithley 2400 SourceMeter controlled via a GPIB-USB adapter. It provides a complete suite of complementary measurement and stability-testing modes that together cover the full characterisation workflow recommended by international consensus protocols [Khenkin et al., 2020].

Measurement modes

ModeShortcutPurpose
J-V Measurement Alt+F2 Forward and reverse voltage sweeps; extracts Voc, Jsc, FF, PCE, Rs, Rsh, and Hysteresis Index (HI)
Light-Intensity J-V Alt+F3 J-V sweeps at user-defined illumination intensities; extracts the light ideality factor nidL from the slope of Voc vs ln(L)
MPP Tracking (JV-SPO) Alt+F5 Cyclic J-V scans followed by Stabilized Power Output (SPO) phases at Vmpp; tracks efficiency evolution over time with periodic J-V diagnostics
Stabilized Current Alt+F6 Holds cell at a fixed voltage and records current density over time; reports quasi-steady-state PCE and detects the stabilization point
Pure MPP Tracking (P&O) Alt+F7 Continuous Perturb-and-Observe maximum power point tracking; records Vmpp, J, and PCE at every time step with no interruptions for J-V scans
Data Curation Alt+F8 Batch analysis of multiple saved J-V files; applies quality thresholds, groups devices by composition, and exports curated statistics ready for Origin box plots
ISOS Protocols (D-1 / L-1 / V-1) Alt+F9 Consensus stability testing: dark storage, continuous light soaking, and dark electrical-bias stress; tracks normalised PCE and stability metrics (T80, T95, …) over days with durable autosave and crash recovery

Key features

  • J-V scanning with configurable voltage range, step size, and timing (delay per point, NPLC); calculates all standard PV parameters automatically
  • Pre-bias conditioning before the reverse scan for reproducible hysteresis measurements following best-practice protocols [Christians et al., 2015]
  • Dark J-V measurement option within the J-V mode to characterise diode behaviour without illumination
  • Stabilized Current / PCE measurement at a fixed bias voltage with automatic stabilization detection
  • MPP Tracking in two protocols: JV-SPO cycling (with per-cycle J-V diagnostics) and pure P&O continuous tracking
  • Data Viewer window for opening and plotting any previously saved Excel file, with metadata panel and interactive legend
  • Data Curation (Alt+F8) — batch analysis of multiple J-V files with composition grouping, configurable pass/fail thresholds, per-group statistics, champion cell identification, and hysteresis summary; exports multi-sheet Excel ready for Origin
  • All data exported to Excel (.xlsx) using a unified row1=headers / row2=metadata / row3+=data layout compatible with downstream analysis
  • Scan rate input — toggle between Advanced mode (enter delay directly) and Scan Rate mode (enter mV/s target, delay auto-calculated)
  • Auto-update via Help → Check for Updates — downloads and applies the latest release in place without reinstalling
  • Built with Python/Tkinter — runs on Windows 10/11 without MATLAB or LabVIEW

3. Driver Installation

⚠ Critical Warning
The KI-488 driver installs a DLL (GPIB32.DLL) with the same filename as the National Instruments DLL. Having both drivers simultaneously or installing them in the wrong order causes silent DLL conflicts that prevent VISA from detecting any instruments. Always follow the order below and restart after each major step.
Step 1 — Clean the system (do this first, hardware DISCONNECTED)
  1. Disconnect the KUSB-488B from all USB ports.
  2. Via Control Panel → Programs → Uninstall, remove all of the following if present: NI-VISA, NI-488.2, NI GPIB, KI-488, Keithley I/O Layer, KUSB-488B drivers.
  3. In Device Manager, uninstall any remaining GPIB/KUSB entries (check "Delete the driver software").
  4. Restart the PC.
Step 2 — Install the KI-488 driver in NI-compatible mode (hardware DISCONNECTED)
  1. Download from tek.com/keithley → Support → Software → search "KUSB-488B".
  2. Run setup.exe. When asked for driver mode, select "NI command-compatible". Do not select "Keithley mode" (incompatible with PyVISA).
  3. Complete the installation. Restart the PC before connecting the cable.
Step 3 — Install NI-VISA runtime (hardware DISCONNECTED)
  1. Download NI-VISA from ni.com/visa (free; requires NI account).
  2. Install NI-VISA runtime only. Uncheck NI-488.2, NI-DAQmx, and all other components.
  3. Restart the PC.
Step 4 — Connect and verify
  1. Connect KUSB-488B to USB. Connect GPIB cable to Keithley 2400 (powered on).
  2. Open KI-488 Configuration Utility. Confirm GPIB0 appears and the Keithley is detected at its address (default GPIB address 21).
  3. Send *IDN? — response should be KEITHLEY INSTRUMENTS INC.,MODEL 2400,...
  4. VISA resource address format: GPIB0::21::INSTR

4. Software Installation

  1. Install Python 3.9+ from python.org. Check "Add Python to PATH" during installation. Use the 64-bit installer.
  2. Open a terminal in the project folder: 
    cd "path\to\jv-measurements"
  3. Install all dependencies: 
    pip install pyvisa numpy matplotlib xlsxwriter openpyxl mplcursors playsound
    If playsound fails to install, omit it — the software falls back to winsound.Beep.
  4. Launch the software: 
    python main.py
ℹ Note
The software stores no data outside the project folder and makes no registry entries. To uninstall, simply delete the project folder.

Automatic updates

The software checks for a newer version automatically 3 seconds after startup (silently, in the background) and can also be triggered manually via Help → Check for Updates.

When a newer version is available, a dialog offers to download and apply it automatically. The update is downloaded as a ZIP archive from GitHub Releases and extracted directly over the installation directory — no reinstallation or re-running of install.bat required. Only updated files are overwritten; measurement output files saved in custom folders are never affected.

ℹ Requires internet connection
The update check and download require a working internet connection. If the check fails (no internet or GitHub unreachable), the background check is silently skipped. An error message is shown only when triggered manually via Help → Check for Updates.

5. Connecting the Instrument

  1. Launch python main.py.
  2. Go to Instrument → Connect…. The dialog scans all VISA resources and queries each with *IDN? to identify devices.
  3. Select the Keithley 2400 entry (GPIB0::21::INSTR) and click ✔ Connect.
  4. The connection is persistent for the entire session. All four measurement modes share this connection. Disconnect via Instrument → Disconnect.

2-wire connection (default)

  • Force HI (red) → counter-electrode (Au/Ag back contact)
  • Force LO (black) → transparent front electrode (FTO/ITO)

4-wire connection (Kelvin sensing)

Use when accurate Rs is required. Enable via the Instrument Settings panel. Connects two additional Sense terminals directly at the cell contacts, eliminating cable resistance from the voltage reading. Sends :SYST:RSEN ON to the Keithley.

  • Force HI / Force LO: same as 2-wire above
  • Sense HI / Sense LO: connect as close to the cell pads as possible

6. Interface Guide

Instrument status banner (dark top bar)

Shows the current connection state. Yellow warning = no instrument connected; measurement buttons are disabled. White text = instrument identified; measurement can proceed.

Mode switching

Eight modes are accessible from the Procedures menu or via keyboard shortcuts (Alt+F2, F3, F5, F6, F7, F8, F9). Each mode reveals its own panel of controls in the left pane. Only one mode can be active at a time. Switching mode does not disconnect the instrument.

J-V mode panel (Alt+F2)

Sample name, export folder, voltage sweep parameters, cell area, instrument settings, illumination input, pre-bias conditioning, and dark J-V option. Contains the main J-V plot area and measurement log.

Light-Intensity J-V panel (Alt+F3)

Standard scan parameters (shared with J-V mode) plus an intensity sequence list. The software prompts you to adjust the solar simulator at each intensity step, waits a configurable stabilization time, then runs a forward + reverse J-V scan. Outputs a consolidated workbook with all curves and the fitted light ideality factor nidL.

MPP Tracking panel (Alt+F5)

Sample name, export folder, cell area, scan parameters, pre-bias option, illumination, total duration, SPO duration per cycle. Contains SPO plot and J-V per cycle overlay.

Stabilized Current panel (Alt+F6)

Sample name, export folder, cell area, applied voltage, illumination, duration, reading interval, and stabilization threshold. Contains a live dual-axis plot (J and PCE vs time).

Pure MPP Tracking panel (Alt+F7)

Sample name, export folder, cell area, perturbation step, interval, NPLC, delay, illumination, and initial scan parameters. Contains dual-axis plot (PCE and Vmpp).

Data Curation panel (Alt+F8)

Multi-file batch analysis tool. Four tabs: Files (load .xlsx files), Groups (define composition groups), Thresholds (set minimum quality thresholds), and Output (export filename and folder). The right panel shows a Raw Data Preview for the selected file and a summary table of all loaded cells with pass/fail coloring.

ISOS Protocols panel (Alt+F9)

Stability-testing workspace for the ISOS-D-1, L-1, and V-1 protocols. A tabbed control area (Experiment / Scan / Instrument / Conditioning, plus L-1 and V-1 sub-frames) feeds a single per-experiment tracking workbook. The right pane shows a live measurement-history table (D-1), a Stability Metrics panel, an ETA + autosave-health status bar, and a protocol-specific plot. Covered in detail in Sections 17–23.

File menu

  • Open Data File… — opens the Data Viewer window for any saved .xlsx file
  • Export Measurement Log… — saves the J-V session log as plain text

7. Measurement Modes Overview

The modes complement each other within a complete efficiency-and-stability characterisation workflow. The order below reflects the recommended characterisation sequence for a new perovskite cell, ending with long-term ISOS stability testing.

Dark J-V (within J-V mode) 1–5 min Dark diode curve, Rsh estimate First measurement; diagnoses shunting and contact quality before illumination
J-V Measurement 2–10 min Voc, Jsc, FF, PCE, Rs, Rsh, HI Primary characterisation; always include forward + reverse scans for HI reporting
Stabilized Current 1–5 min Quasi-steady-state J and PCE at fixed V Quick validation of dynamic J-V PCE; reports stabilized efficiency after transients decay

ℹ Recommendation for efficiency reporting
Per the ISOS consensus [Khenkin et al., 2020], a credible efficiency claim for perovskite solar cells requires: (1) J-V scans in both directions with reported scan rate and HI, AND (2) a stabilized PCE from MPP tracking or Stabilized Current measurement over ≥60 s.

8. J-V Measurement Parameters Alt+F2

Start Voltage (V)
Default:−0.1 V

Starting point of the forward scan. Setting slightly below 0 V ensures Jsc plateau is fully captured and zero-crossing for Rsh extraction is reliable. Avoid values below −0.5 V (risk of degrading organic transport layers).

End Voltage (V)
Default:1.05 V

Should be slightly above the expected Voc to ensure the zero-crossing is captured. For typical FA/MA perovskites (Voc ≈ 1.0–1.15 V), use 1.1–1.2 V. Setting below Voc makes Voc extraction impossible.

Step Voltage (V)
Default:0.025 V (25 mV)

Voltage increment between measured points. Smaller steps improve the accuracy of Jsc, Voc, and MPP extraction. Typical range for perovskites: 10–50 mV. The Scan Rate (mV/s) field updates automatically to reflect the effective rate with the configured step, delay, and NPLC.

scan rate (mV/s) = Step (mV) / (DelayHW + NPLC / fgrid + 20 ms) × 1000

The 20 ms is a fixed Python-side overhead per point. The displayed scan rate is saved in the Excel file.

Cell Area (cm²)
Default:0.07 cm²

Used to convert measured current (A) to current density (mA/cm²). A 5% area error propagates directly to 5% error in Jsc and PCE. When using an aperture mask, enter the mask opening area, not the total cell area.

Scan rate reference table

Brazil grid 60 Hz; 1 NPLC ≈ 16.7 ms. The 20 ms software overhead is included.

9. Instrument Settings

Delay per point (ms)
Default:100 ms
SCPI::SOUR:DEL {value}

Hardware delay set on the Keithley between applying a voltage step and triggering the ADC. More precise than a Python sleep because it is handled by the instrument firmware. For perovskites, 100–500 ms is recommended to allow slow ionic redistribution to partially settle before the current reading [Tress et al., 2015].

⚠ Note for publications
Always report delay per point and NPLC when publishing J-V data on perovskites. Both values are saved automatically in the Excel output.
NPLC (Number of Power Line Cycles)
Default:1.0
Range:0.01 – 25
SCPI::SENS:CURR:NPLC {value}

Integration time of the Keithley ADC. At 60 Hz, 1 NPLC = 16.7 ms. Higher NPLC averages out more 60 Hz noise at the cost of slower scan speed. Use NPLC 5–10 for dark J-V where currents are in the nA–μA range; NPLC 1.0 is sufficient for illuminated measurements.

4-Wire (Kelvin) sensing
Default:OFF
SCPI::SYST:RSEN ON / OFF

Removes cable and contact resistance from the voltage measurement. Improves Rs accuracy by 0.5–2 Ω·cm² in typical setups. Recommended when comparing transport layer conductivities or when cable length is >1 m.

Scan Rate Input Mode

The Instrument Settings panel provides two complementary ways to control measurement timing:

  • Advanced mode (default): enter Delay per point directly (milliseconds). The Scan Rate (mV/s) field is computed automatically and shown read-only, so you can verify the effective rate at a glance without arithmetic.
  • Scan Rate mode: click the Scan Rate → toggle button to switch. Enter a target scan rate in mV/s; the software back-calculates the delay as: 
    delay = (step_mV / rate_mV_s × 1000) − NPLC × 16.7 − 50 ms
    The 50 ms constant accounts for GPIB overhead. The result is clamped to 0 ms when the formula yields a negative value. A ⚠ symbol is appended to the displayed scan rate when the delay was clamped, indicating the hardware cannot sustain the requested rate and the actual effective rate will be slightly slower.

Both modes write the same parameters to the Excel output: Delay per point → column U; Scan Rate → column AA.

Tip — scan rate consistency
When comparing hysteresis across multiple cells or experiments, always use the same scan rate. Enter the target rate in Scan Rate mode to guarantee identical effective rates regardless of which step size you choose.

10. Shutter Control

Almost every measurement in this software depends on knowing whether the cell is illuminated. A dark J-V that silently ran under light looks perfectly plausible in the data — nothing about the curve announces the mistake. The software therefore treats the shutter as something to be commanded and asserted, not assumed.

Shutter support is pluggable. The software ships with three backends and is designed so that a lab with different hardware can add its own, or in the common case simply configure the generic serial backend and write no code at all.

Where to find it
Instrument → Shutter Control… on the menu bar. It lives there rather than inside one measurement panel because the shutter belongs to the rig: one configuration serves J-V, Light-Intensity, MPP, Pure MPP, Stabilized Current and every ISOS protocol. The setting is saved to ~/.jv-measurement/settings.json and restored the next time the software starts.

The Shutter Control window

System

Chooses the backend. The settings shown underneath change to match — each backend declares its own options, so the form is different for each one.

Manual:the software prompts you; you move the shutter by hand
Keithley 2600 digital I/O:a digital I/O line of the SourceMeter drives the shutter
Serial / Arduino:text commands over a serial port
Apply & Save

Validates the form, activates the backend and writes the configuration to disk. Out-of-range values are refused with an explanation rather than silently clamped.

Test: Open / Test: Close / Self-test

Move the shutter right now, so you can confirm the wiring without starting a measurement. Self-test performs close → open → close and reports how long each step took. All three apply the form first, so there is no "I forgot to click Apply" failure mode — what you see on screen is what gets tested.

The buttons are refused while a measurement is running: the shutter shares the instrument's connection, and moving it mid-scan would corrupt the data even if it were electrically safe.

Status badge

Top right of the window. Reads CLOSED (green), OPEN (orange), manual, or unknown (connect instrument) in grey. "Unknown" is honest rather than defensive: before the SourceMeter is connected, a backend that borrows its connection genuinely cannot know where the shutter is.

When the shutter moves

Once an automatic backend is configured, the software drives the shutter at every boundary, in every mode:

Nothing changes if you do not configure a shutter
With the default Manual backend the software behaves exactly as it always has: it prompts you at the dark/illuminated handover in J-V and ISOS-D-1, and at the ISOS-V-1 scan boundaries — no more dialogs than before, and no fewer. The extra boundaries in the table above are driven only by backends that can actuate on their own.

10.1 Manual backend

The default. At each dark/illuminated boundary the software pauses, shows a dialog asking you to open or close the shutter, and waits for OK. Choose this if your simulator's shutter has no remote input, or while you are still wiring up an automatic one.

10.2 Keithley 2600 digital I/O backend

The SourceMeter's own rear-panel DIGITAL I/O connector drives the shutter. This needs no extra instrument and no extra software, which is why it is the first automatic backend the software shipped with.

The connector

A 25-pin female D-sub on the rear panel of any Series 2600 instrument:

PinsFunction
1 – 14Digital I/O lines #1 – #14 (the line number equals the pin number)
15 – 21Ground
22, 23, 25+5 V output (600 mA total, self-resetting fuse)
24Interlock (2611/2612/2635/2636) or Output Enable (2601/2602) — not a digital I/O line; the software never writes it

Electrical behaviour — read this before wiring

Each line is an open-drain output with a 5.1 kΩ pull-up to +5 V. Three consequences follow, and every one of them matters:

  • A line idles HIGH. Nothing driving it means +5 V, not 0 V.
  • It can barely source current. About 960 µA maximum flows out of a line when high. That is enough for a high-impedance TTL input and nothing else.
  • It sinks far more than it sources. Up to 5 mA at 0.7 V, 11 mA absolute maximum, flowing into the line. This is why interface boxes are normally built so that the Keithley pulls a line low to activate an opto-isolator or relay powered from the port's own +5 V pin.
⚠ The fail-safe question
Because the lines idle high, a non-inverting interface leaves the shutter OPEN whenever the SourceMeter is powered on and nothing is driving the line. That is the opposite of fail-safe, and it is a property of the wiring, not of the software. An inverting interface (Keithley pulls low to open) idles closed and is the safer arrangement. Use probe_shutter.py (below) to find out which one you have — the software reports it too, and says so explicitly in the result.

A useful guarantee on the instrument side: the Series 2600 reference manual states that "the reset function does not affect the present state of the digital I/O lines". The *RST the software sends before every scan therefore never disturbs the shutter.

ABET Sun 2000 / Sun 3000 wiring

ABET simulators expose a SHUTTER INPUT BNC whose meaning depends on the front-panel SHUTTER CONTROL switch:

Switch positionWhat the BNC does
EXTERNALLevel sensitive: the shutter stays open as long as a TTL +5 V signal is present. This is the mode to use.
INTERNAL / TIMEDEdge trigger: a switch closure or a low TTL state fires one exposure of the built-in timer's duration, then the shutter closes by itself.
⚠ Put the switch in EXTERNAL
The software cannot see the position of that switch. Left in INTERNAL/TIMED, an "open" command becomes a timed exposure that ends on its own part-way through your scan — with no error, just wrong data. Check it before every session, or leave it taped in place.

ABET also warns that running the shutter faster than 3 Hz for extended periods overheats the solenoid. Normal use here is far below that: at most one open and one close per measurement.

Finding your line and polarity — probe_shutter.py

You cannot guess which digital I/O line is wired, or which level opens the shutter. The repository includes a bench tool that finds out without touching the instrument's front panel. Run it from the project folder:

python probe_shutter.py            # manual: watch the simulator's LED
python probe_shutter.py --auto     # automatic: the SMU watches, via cell current
python probe_shutter.py --read     # read the port state only, write nothing
python probe_shutter.py --poke 3 0 # hold one line at one level until you press Enter
python probe_shutter.py --lines 1-8  # restrict the range if other kit shares the port

It perturbs one line at a time, restores each one immediately, and always restores the whole port on exit — including on Ctrl+C. Start with --read, which writes nothing at all.

Manual mode asks you to watch the red SHUTTER LED on the simulator and answer y/n per line; run it with the lamp off so nothing gets illuminated. --auto is more reliable: with the lamp on and a cell connected, the SourceMeter itself detects the change in photocurrent, needs no operator input, and additionally times how long the blade takes to travel.

The result is printed in the form the Shutter Control window wants:

  Digital I/O line ......... #1  (DB-25 pin 1)
  Opens the shutter ........ digio.writebit(1, 1)
  Closes the shutter ....... digio.writebit(1, 0)
  Polarity ................. ACTIVE HIGH
  Resting state ............ OPEN    -> NOT fail-safe
  Mechanical settling ...... 68 ms

      line       = 1
      active_low = False
      settle_ms  = 68

Settings

Range:1 – 14

Which line is wired to the shutter. Equals the DB-25 pin number.

HIGH opens the shutter
Default:checked

Checked for a non-inverting interface (write 1 to open); unchecked for an inverting one (write 0 to open). See the fail-safe warning above.

Settling time (ms)
Default:300 ms

How long to wait after commanding, for the blade to finish moving. Measure it with probe_shutter.py --auto and then use a comfortable multiple: this happens once or twice per measurement, not once per point, so margin costs nothing. A typical ABET Sun 2000 blade takes about 70 ms; 300 ms is the default.

This is the blade, not the cell
Settling time covers the mechanical travel only. A perovskite's own response to light is a separate, far slower effect measured in seconds to minutes — that is what the Light Soaking setting is for. Do not use one in place of the other.
Verify the line after writing
Default:checked

Reads the line back with digio.readbit and fails if it did not take the commanded level. Catches a write-protected line (digio.writeprotect) or one being held by another device. Costs one extra query per move.

10.3 Serial / Arduino backend

This is the generic backend, and the reason the abstraction exists. Rather than shipping "an Arduino driver", the software ships a configurable text-command backend: you type the words your controller expects into the settings form. The same code therefore drives a home-made Arduino box and most commercial shutter controllers, which are all ASCII over a serial port with different vocabulary.

Requires pyserial

It is imported only when the backend is actually used, so a machine without it still runs the software normally — including with this backend stored in the settings file.

Without it, the software sends a command and trusts that it worked. With it, the controller is asked to confirm, and a disagreement stops the measurement instead of quietly recording a scan under the wrong illumination. It is the single most valuable field in this form.

Building an Arduino shutter controller

An example sketch ships with the software at docs/arduino_shutter.ino. It answers OPEN, CLOSE and STATE at 9600 baud, and needs no modification for the default settings above.

Wiring. The sketch drives pin 8. An Arduino pin sources about 20 mA at 5 V, which is enough for:

  • a TTL input such as the ABET SHUTTER INPUT BNC (centre pin to the Arduino pin through a series resistor, shield to Arduino GND — grounds must be common);
  • the input of an opto-isolator or a relay module (a board with its own driver transistor).

It is not enough to drive a solenoid or a bare relay coil directly. Those need a driver board, and the solenoid needs its own supply.

Polarity and fail-safe. The sketch closes the shutter in setup() before doing anything else, so a power cycle or a reset leaves the cell dark. If your interface inverts the signal, change ACTIVE_HIGH to false in the sketch rather than swapping the OPEN and CLOSE commands in the software — swapping the words would leave the sketch closing the shutter into the wrong physical state at reset, defeating the fail-safe.

10.4 Verification with an SMU reading

A shutter can only report what it was told to do. The SourceMeter can report what the cell actually sees, and that is the only closed-loop check available.

Tick "Confirm the light state with an SMU reading" in the Shutter Control window and, after every move, the software reads the cell current at 0 V and checks it against the state it asked for: bright when opened, dark when closed. A dark cell reads nanoamps and a lit one milliamps, so the default threshold of 0.001 mA (1 µA) sits three orders of magnitude from both.

This is the check that catches the dangerous case on non-fail-safe wiring: a dark scan that silently ran illuminated. A mismatch asks whether to continue or abort; a failure of the check itself never fails a run.

Off by default
It needs a cell connected and the lamp on, which is not true of every session — a dark-only characterisation, for instance. Turn it on for unattended or long-running work, where nobody is watching the simulator.

10.5 Startup, connect and shutdown

The software asserts a closed shutter as early as the hardware allows:

  • Backends that need no SourceMeter (the serial one) are closed about 200 ms after the application starts, before anything is connected. This is the full form of the guarantee.
  • Backends that borrow the SourceMeter's connection (the Keithley digital I/O one) are closed the moment the instrument connects — the first point at which they can be commanded at all.
  • On disconnect and on exit, the shutter is closed before the connection is released. Afterwards there would be no way to command it.
⚠ The gap the software cannot close
With a non-fail-safe Keithley wiring, the shutter may already be open between switching the SourceMeter on and connecting to it in the software. No program can prevent that — nothing is listening yet. The status badge reads "unknown (connect instrument)" for exactly this period rather than pretending otherwise. If it matters for your samples, either connect before switching the lamp on, or have the interface box inverted so the resting state is closed.

The Shutter Control window builds its settings form from the backend's declared fields tuple, so a contributor who can write sixty lines of Python can add their own hardware without touching tkinter.

10.7 Shutter troubleshooting

❌ The shutter does not move at all
Causes: SHUTTER CONTROL switch not in EXTERNAL; wrong digital I/O line; the interface box has no power; the cable does not carry the ground or +5 V pin the box needs.
Solutions:
  1. Put the simulator's SHUTTER CONTROL switch in EXTERNAL.
  2. Run python probe_shutter.py --read to confirm the software can talk to the port at all (it writes nothing).
  3. Run python probe_shutter.py and let it scan all 14 lines. If no line responds, the problem is on the wiring side, not in the software.
  4. Try --auto with the lamp on: a cell current reading is a far more reliable witness than an LED at the edge of your vision.
❌ The shutter opens when it should close, and vice versa
Cause: The polarity setting does not match your interface box.
Solution: Toggle "HIGH opens the shutter" in the Shutter Control window and click Apply & Save, then Self-test. If in doubt, let probe_shutter.py determine it — it reports the polarity explicitly.
❌ "Digital I/O line N was set to X but reads back as Y"
Causes: the line is write-protected (digio.writeprotect is non-zero), or another device on the port is holding it.
Solutions:
  • Run python probe_shutter.py --read; it prints the write-protect mask.
  • Check whether another instrument shares the DB-25. If so, use --lines to keep the probe away from its line, and make sure the shutter is configured for a line nothing else drives.
  • As a last resort the check can be switched off with "Verify the line after writing" — but you then lose the only warning you would get about a stuck line.
❌ The shutter is open whenever the Keithley is switched on
Cause: Not a fault. The 2600's digital I/O lines idle HIGH through a 5.1 kΩ pull-up, so a non-inverting interface holds the shutter open whenever nothing is driving the line.
Solutions:
  • Connect the instrument in the software — it closes the shutter immediately on connect.
  • For a permanent fix, have the interface box inverted so that the Keithley pulls the line low to open. The resting state then becomes closed, and the software configuration is simply "HIGH opens" unchecked.
  • Switch the SourceMeter off when leaving the bench: with no power there is no pull-up, and the line falls.
❌ A dark measurement looks illuminated (or the reverse)
Causes: SHUTTER CONTROL left in INTERNAL/TIMED, so the "open" became a timed exposure that ended mid-scan; the beam is blocked by something other than the shutter; the lamp is off.
Solutions:
  1. Enable "Confirm the light state with an SMU reading". This is exactly the failure it exists to catch, and it will stop the run instead of saving a plausible-looking wrong curve.
  2. Check the SHUTTER CONTROL switch is in EXTERNAL.
  3. Run python probe_smu.py with the lamp on and the shutter open. It steps through voltages on both SMU channels and says whether it is seeing a lit cell, a dark cell, or nothing connected.
❌ Serial backend: "Could not open serial port"
Causes: wrong port name; the Arduino IDE's Serial Monitor (or another program) already has the port open; missing driver.
Solutions:
  • Close the Arduino Serial Monitor. Windows gives a serial port to one program at a time.
  • Confirm the port name in Device Manager under Ports (COM & LPT).
  • Install the board's USB-serial driver (CH340 clones in particular need one).
❌ Serial backend: "did not answer within N s"
Causes: wrong baud rate; wrong line ending; the controller has no state query; the reply arrives after the timeout.
Solutions:
  • Check baud rate and line ending against the controller's manual. An Arduino using readStringUntil('\n') needs LF.
  • Raise Reply timeout.
  • If the controller genuinely cannot report its state, clear the State query field. The software will then trust the command instead of verifying it.
❌ Arduino: the first command after connecting is lost
Cause: Most Arduino boards reset when the serial port is opened (the DTR line is wired to reset), and then spend a second or two in the bootloader, discarding anything sent meanwhile.
Solution: Raise Delay after opening the port to 2 s or more. The software opens the port once and keeps it open, so this cost is paid a single time per session, not per shutter movement. Boards that do not reset on DTR can use 0.
❌ "This shutter backend needs pyserial"
Cause: pyserial is not installed in the Python environment running the software.
Solution: pip install pyserial, then restart the software. It is deliberately an optional dependency: the import happens only when the backend is actually used, so its absence never prevents the application from starting.
❌ The Test buttons do nothing and say a measurement is running
Cause: Not a fault. The shutter shares the instrument's connection, and moving it mid-scan would invalidate the data.
Solution: Stop the measurement first. If no measurement is actually running, the software may have been left in that state by an error — Instrument → Disconnect and reconnect clears it.
❌ "The shutter could not be opened automatically"
Cause: Two consecutive failures — the software already retried once before asking.
Solution: The dialog offers to continue with a hand-moved shutter (OK) or abort the measurement (Cancel). Both are safe choices; what the software will never do is carry on silently with an unknown illumination state. Afterwards, use Self-test to reproduce the failure with its full error message.
❌ The shutter chatters, or the solenoid gets hot
Cause: Too many open/close cycles. ABET warns against sustained operation above 3 Hz.
Solution: Normal use is far below that limit — one open and one close per measurement. If you see rapid cycling, something is calling the shutter in a loop: check that an ISOS protocol is not configured with a scan interval of seconds, and report it as a bug if not.

11. Pre-bias Conditioning

Physical motivation

Perovskite absorbers are mixed ionic-electronic conductors. Mobile ionic species (primarily iodide vacancies VI+ and interstitial ions) redistribute slowly (seconds to minutes) in response to the electric field. If J-V scans begin from an unknown ionic state, the results are irreproducible.

Applying a forward bias slightly above Voc for 2–5 s drives ions to a well-defined accumulation state at both interfaces, ensuring all reverse scans start from the same ionic configuration. This makes the HI value reproducible and comparable between experiments [Christians et al., 2015].

Measurement sequence when pre-bias is enabled

Forward scan (no pre-bias)
→
Pre-bias hold
→
Reverse scan
ℹ Why this order?
Pre-bias is applied only before the reverse scan. Conditioning before the forward scan would distort FS results and make the HI calculation physically meaningless.
Pre-bias Voltage (V)
Default:1.2 V

Set 0.1–0.2 V above the expected Voc. For FA/MA perovskites with Voc ≈ 1.0–1.1 V, 1.2 V is appropriate. Avoid values far above Voc (>1.5 V for a 1.1 V cell) to prevent degradation.

Pre-bias Duration (s)
Default:2.0 s

Literature recommendation: 2–5 s [Christians et al., 2015]. High-ionic-density absorbers or thick films may need up to 10 s for full equilibration.

13. Light-Intensity J-V Alt+F3

What it measures

This mode runs a sequence of J-V scans at several illumination intensities and extracts the light ideality factor nidL from the dependence of the open-circuit voltage on light intensity. It is the standard technique for distinguishing the dominant recombination mechanism in a solar cell without requiring dark measurements [Tress et al., 2018; Caprioglio et al., 2020].

Theory — why Voc vs ln(L) reveals recombination

In the ideal-diode picture the open-circuit voltage depends logarithmically on the photogenerated current, and therefore on illumination intensity L:

Voc = (nidL kBT / q) · ln(L / L0) + const

Plotting Voc against ln(L) yields a straight line whose slope is nidL·kBT/q. The software normalises intensity to its maximum (Lnorm = L / Lmax) so only intensity ratios matter — the absolute unit (suns, %, mW/cm²) is irrelevant. The slope is converted to the ideality factor through nidL = q·slope / (kBT).

nidLDominant recombinationInterpretation
≈ 1Band-to-band / radiative or surface (majority-carrier)High-quality absorber, well-passivated interfaces
≈ 1.3–1.6Mixed bulk + interfaceTypical for good perovskite devices
≈ 2Shockley–Read–Hall (trap-assisted, bulk depletion region)Defect-limited; deep traps in the bulk
> 2Interface / ionic / multi-trapStrong interfacial or ion-mediated recombination

Parameters

An ordered list of illumination intensities (in suns or any consistent proportional unit). At each step the software prompts you to set the solar simulator to that intensity and confirm before continuing. Use at least 4–5 well-spaced intensities spanning roughly 0.1–1 sun for a reliable slope; the fit requires a minimum of 3 points.

Stabilization time (s)

Wait time after you confirm a new intensity, before the J-V scan starts. Allows the lamp and cell to settle. A live countdown is shown. 10–30 s is typical.

The mW/cm² value corresponding to 1 sun for your reference detector, used to convert each intensity step into an absolute Pin for the PCE of that step.

Output is a consolidated workbook containing all J-V curves, the per-intensity PV parameters, and the fitted nidL with its standard error and R². The fit is also viewable later in the Data Viewer (Section 26).

Tip — clean fits
Always include a 1-sun point and at least one point below 0.3 sun. A poor R² (<0.99) usually means the simulator intensity drifted between steps or the stabilization time was too short.

14. Stabilized Current Measurement Alt+F6

What it measures

The cell is held at a constant user-defined voltage while the current density and PCE are read at regular intervals. The measurement continues for the configured duration and automatically detects the point at which the cell output has stabilized.

Unlike a J-V scan, this measurement captures the quasi-steady-state response of the cell. Perovskite cells often show transient current behaviour immediately after a voltage step; the stabilized current measured after these transients decay is a more physically meaningful efficiency metric than the dynamic J-V scan value [Snaith et al., 2014].

Parameters

16. Pure MPP Tracking — Perturb & Observe Alt+F7

Algorithm description

The Perturb-and-Observe (P&O) algorithm is the most widely used method for maximum power point tracking in photovoltaic systems [Hohm & Ropp, 2003]. At each step, the algorithm applies a small voltage perturbation (±Δv) and compares the resulting power with the previous reading:

  • If power increased → continue in the same direction (perturbation was toward MPP)
  • If power decreased → reverse direction (perturbation was away from MPP)

This oscillates around Vmpp with an amplitude of ±Δv. A smaller Δv gives a more precise estimate of Vmpp at the cost of slower tracking response to changes in illumination or cell state.

Measurement sequence

Initial reverse J-V scan
→
Find Vmpp
→
P&O loop (continuous)
→
Output OFF, save Excel

The software first performs one reverse J-V scan to find the real Vmpp from the measured J-V curve, then enters the continuous P&O loop starting from that voltage. The time axis on the plot starts at t = 0 after the initial scan, so the plot shows only the P&O tracking phase.

Parameters

Perturbation Step (V)

Voltage step Δv applied at each iteration. Smaller values (0.005–0.010 V) track Vmpp more precisely; larger values (0.01–0.02 V) respond faster to drifting Vmpp.

Step Interval (ms)

Time between P&O perturbations. The inter-step wait is broken into 50 ms chunks internally so the Stop button is checked frequently. Shorter intervals increase tracking speed; longer intervals allow more time for ionic equilibration after each step.

Initial Scan Parameters

Voltage range (scan_start_v, scan_end_v) and step size for the initial reverse J-V scan. These determine the starting Vmpp estimate. The J-V scan result is also shown in the plot for reference.

Live plots

  • J plot: current density J at Vmpp vs time.

17. Dark J-V Measurement Alt+F2 (within J-V mode)

What it measures

The dark J-V scan applies the standard forward + reverse voltage sweeps with the solar simulator shutter closed. Without illumination, the measured current reflects the dark diode characteristics of the device — exponential forward-bias injection current and leakage (shunt) current near zero bias.

Dark J-V measurements are used to:

  • Estimate Rsh before illumination (the slope near V = 0 in the dark is a direct measure of shunting paths)
  • Extract the ideality factor n and dark saturation current J0 of the diode
  • Diagnose contact and transport layer quality independently of illumination uniformity
  • Detect resistive heating artefacts in the illuminated measurement by comparison

How to use

Enable "Include Dark J-V scan" in the J-V measurement panel. When the measurement starts, the software performs the dark scan (shutter closed) first, prompts you to open the shutter, then proceeds with the illuminated scans.

Dark J-V data is saved to a separate Excel file (_Dark_JV_ in the filename) with the sheet name Dark_JV_Data. No PCE, FF, or Voc values are extracted (those parameters have no physical meaning in the dark).

⚠ Sign convention
The software applies a sign inversion to the raw Keithley current reading (current = −float(reading)) to place photocurrent in the positive (power-generating) quadrant per standard solar cell convention. In the dark, forward-bias current (injection) appears as negative J in the plot — this is correct.

18. ISOS Protocols Overview Alt+F9

What ISOS is

ISOS (International Summit on Organic and Hybrid Photovoltaic Stability) is a set of consensus stability-testing protocols agreed by the perovskite and organic PV community and published in Nature Energy [Khenkin et al., 2020]. They define how a cell should be stressed (dark, light, electrical bias, thermal, outdoor), under which load (open circuit, maximum power point, or short circuit), and how the resulting degradation should be reported, so that lifetimes measured in different laboratories are comparable.

A protocol name encodes the stress family and a level: D = dark storage, L = light soaking, V = electrical bias (voltage), T = thermal cycling, LC = light cycling, O = outdoor. The level (1, 2, 3) sets the environmental control: level 1 is ambient / minimal control, levels 2–3 add controlled temperature, humidity, or atmosphere. This software implements the level-1 protocols that need no additional environmental hardware.

20. ISOS-D-1 — Dark Storage / Shelf Life

Protocol

The cell is stored in the dark at open circuit and periodically taken out for an illuminated J-V characterisation. This is the gentlest ISOS test and measures intrinsic shelf life — how the device ages with no light or applied bias. There is no automated stress loop: you trigger each characterisation manually by pressing "Run ISOS", typically once per day.

How to run a D-1 campaign

  1. Select ISOS-D-1, set sample name and export folder, then click New Experiment. This stamps t₀.
  2. Set the scan, illumination, instrument, and conditioning parameters (Section 19).
  3. Press Run ISOS. The software runs the same sequence as a normal J-V measurement (optional dark J-V → optional light soak → forward → optional pre-bias → reverse) and appends one row to the tracking workbook with the elapsed time and all PV parameters.
  4. Return the cell to dark storage. The next day, Load Experiment… (or keep the app open) and press Run ISOS again. Elapsed time continues from the original t₀.

Measurement History table

For D-1 the panel shows a live table of every point: index, date, elapsed hours, reverse-scan PCE, and PCE normalised to the first measurement (PCE/PCE₀). A normalised value of 0.80 marks T80 — the canonical lifetime endpoint (Section 23).

Tip — keep the cadence regular
Even sampling (e.g. every 24 h) gives the cleanest degradation curve and the most reliable T80 / T95 extrapolation. Record at least one point before any meaningful aging so PCE₀ is a true fresh-cell baseline.

Core parameters

Total duration (h)

How long the whole stress run lasts (default 24 h). Drives the ETA.

Scan interval (min)

Time between illuminated characterisations (default 15 min). Shorter intervals give finer degradation curves but interrupt the stress more often.

Pre-scan relaxation (s)

A short settle at OC (default 60 s) just before each J-V scan, so the scan starts from a repeatable state rather than straight out of the MPP-loaded stress phase.

SPO after scan (s)

Duration of a stabilized-power-output measurement taken right after each J-V scan (default 20 s; 0 disables it). The SPO PCE is the preferred canonical efficiency for the stability metrics because it is scan-rate independent.

Baseline conditioning

Baseline scans (N) & Baseline rest (s)

Before stress begins, the runner takes N J-V scans (default 4) spaced by the rest time (default 60 s). The first scan is discarded (it is the least settled) and the median PCE of the rest defines PCE₀ — the denominator for all normalised values and the metrics. A robust PCE₀ is what makes T80 trustworthy.

Equilibration before start (h)

Optional dark hold before baseline (default off, 0 h). Used to bring a freshly fabricated cell to a stable starting point.

Load-specific settings

MPP load — Engine, Perturb step, V min/max, MPP log interval

When load = MPP, the cell is held near maximum power during stress. The Engine is either P&O (continuous perturb-and-observe, Section 16) or JV-SPO (periodic mini J-V then hold Vmpp). Perturb step (default 10 mV) is the P&O voltage increment; V min/max (0–1.2 V) clamp the tracked voltage to a safe window; and the MPP log interval (default 2 s) sets how often a stress sample is streamed to the autosave CSV.

OC load — Voc read interval (ms)

When load = OC, the cell sits at open circuit and its Voc is logged every read interval (default 1000 ms).

Failure detection

PCE threshold (% of PCE₀) & Auto-stop

If the measured PCE falls below this fraction of PCE₀ (default 20 %), the cell is flagged as failed. With Auto-stop on failure enabled (default), the run ends cleanly and the data is consolidated; otherwise the run continues and the failure is only logged.

22. ISOS-V-1 — Dark Electrical-Bias Stress

Protocol

The cell is stressed in the dark under a constant applied bias (or held at the last measured Vmpp) and is characterised periodically with both a dark and an illuminated J-V scan. The shutter is opened only briefly for the illuminated scan — the software prompts you (or your shutter hardware) to open and close it around each one. V-1 isolates the effect of electrical bias and field-driven ion migration from photodegradation, and the dark diode is the most sensitive probe of bias-induced shunting and contact damage.

27. Single-Diode Fit

What it does

The single-diode fit extracts the five physical device parameters (Jph, J0, n, Rs, Rsh) by fitting the full implicit diode equation to a measured illuminated J-V curve. Unlike the local-slope estimates of Rs and Rsh (Section 32), the fit uses the entire curve at once, so the parameters are mutually consistent and come with statistical uncertainties.

Theory — the implicit equation

The cell is modelled as a photocurrent source in parallel with a diode and a shunt resistance, in series with Rs (Section 33). In the software's unit convention (J in mA/cm², R in Ω·cm²):

J = Jph − J0·[exp((V + J·Rs·10−3)/(n·VT)) − 1] − (V + J·Rs·10−3)·103/Rsh

Because J appears on both sides, the equation is solved pointwise for J at each voltage with a bracketed root-finder (Brent's method), and these solved values are fed into a non-linear least-squares optimiser (scipy.optimize.curve_fit) that adjusts the five parameters. VT = kBT/q is the thermal voltage (≈ 25.7 mV at 298 K); the fit temperature is editable.

The five parameters

ParameterMeaningEffect on the curve
JphPhotogenerated current density (≈ Jsc)Sets the Jsc plateau height
J0Dark saturation current densityLower J0 → higher Voc (recombination)
nIdeality factorShapes the knee; recombination signature
RsSeries resistanceTilts the curve near Voc (reduces FF)
RshShunt resistanceTilts the curve near Jsc (leakage)

Example fit

Fit overlay (top) and residuals (bottom). A good fit shows residuals scattered randomly about zero with no structure.

Goodness-of-fit metrics

  • R² — coefficient of determination; >0.999 is typical for a clean curve.
  • RMSE — root-mean-square error in mA/cm².
  • RMSE (log) — RMSE in log10|J| space, which weights the low-current region fairly and is the more honest metric across the curve's huge dynamic range.
  • Bounded parameters — any parameter that hit its allowed bound is flagged; a bounded result is a warning that the model could not find an interior optimum (often a sign the curve is distorted, e.g. S-shaped).

How to run it

  • Auto-fit (post-measurement): enable "Auto single-diode fit" on the Instrument tab (default off). The reverse scan is fitted automatically in the measurement thread and the result is written as a SingleDiodeFit sheet in the J-V file.
  • Interactive fit (Data Viewer): open an illuminated J-V file and click Single-Diode Fit. The window shows the overlay and residuals and lets you edit the temperature and parameter bounds, re-fit, export the result to CSV, and save it back into the file.
⚠ When the fit struggles
Strongly S-shaped curves, heavy noise, or a missing Jsc/Voc region can push parameters to their bounds or inflate uncertainties. Widen the bounds, supply a better temperature, or measure a cleaner curve before trusting the extracted J0 and n.

28. Dark J-V Ideality Fit

What it does

A dark J-V curve plotted as log10|J| versus V has a straight exponential region between the shunt-dominated low-voltage part and the series-resistance-limited high-voltage part. The slope of that line gives the diode ideality factor n and its intercept gives the dark saturation current density Js. This is the classic, illumination-independent way to diagnose the dominant recombination mechanism.

Theory

In the exponential injection region the shunt and series terms are negligible, so the diode equation reduces to J ≈ Js·exp(V/(n·VT)). Taking log10:

log10|J| = log10Js + V / (n·VT·ln 10)

so a linear regression of log10|J| on V over the chosen window gives

n = 1 / (VT·ln 10·slope),    Js = 10intercept

The same n-interpretation table as the light ideality factor applies (Section 13): n≈1 radiative/surface, n≈2 trap-assisted SRH, n>2 interface/ionic.

Example fit

Dark |J| on a log axis: shunt plateau at low V, clean exponential region (shaded = fit window), and Rs roll-off at high V.

Choosing the fit window

⚠ The window is everything
The window (default 0.5–0.8 V) must lie inside the straight exponential region. If it dips into the shunt-dominated plateau (too low) the slope flattens and n is over-estimated; if it reaches into the Rs-limited region (too high) the slope also flattens. Always inspect the semilog plot and pick the window over the visibly straight section. At least 5 points must fall inside the window.

How to run it

Open a dark J-V file in the Data Viewer and click Dark Ideality Fit (enabled only for dark files). Adjust the Vmin/Vmax window and temperature, re-fit, and read n, Js, and R². In ISOS-V-1 the dark ideality fit is run automatically on every dark scan using the window set in the V-1 sub-frame (Section 22).

29. Light Ideality Factor

The light ideality factor nidL is produced by the Light-Intensity J-V mode (Section 13), where its full theory is given. It is the slope of Voc versus ln(L) in units of kBT/q, and like the dark ideality factor it diagnoses the dominant recombination mechanism — but it does so under real operating illumination, which is often more representative than the dark diode.

Viewing the result

Open a Light-Intensity workbook in the Data Viewer. The metadata panel reports nidL for the forward and reverse scans with their standard errors and R², any fit warnings, and the plot shows the Voc-vs-ln(L) regression line over the data points (see the example in Section 13).

ℹ Dark vs light ideality
A dark ideality near 2 with a light ideality near 1 (or vice versa) is informative in itself: it means the recombination that limits Voc under illumination differs from the dark injection mechanism — frequently a sign that interfaces, not the bulk, dominate under operation.

34. Hysteresis in Perovskite Solar Cells

Physical origin

Perovskite absorbers are mixed ionic-electronic conductors. Mobile ionic defects (iodide vacancies VI+, interstitial ions Ii−, typical concentrations 1015–1017 cm−3) migrate in response to the electric field during a voltage sweep. Because ions move orders of magnitude more slowly than electrons and holes, their redistribution lags behind the electronic response, creating a time-dependent internal field that depends on the scan direction [Tress et al., 2015; Snaith et al., 2014].

Normal vs. inverted hysteresis

TypeConditionHICommon architecture
NormalPCERS > PCEFSHI > 0n-i-p with TiO₂/SnO₂ ETL
InvertedPCEFS > PCERSHI < 0p-i-n with PEDOT:PSS
NegligibleRS ≈ FS|HI| < 2–3%Well-passivated cells; slow scans

Effect of scan parameters

  • Faster scans → larger apparent HI. HI values are only comparable between measurements performed at the same scan rate.
  • Slower scans → smaller HI. As scan rate → quasi-steady-state, the J-V curve becomes path-independent.
  • Pre-bias conditioning standardises the ionic state before the reverse scan, ensuring reproducible HI values across sessions and laboratories.

Best practices for reporting

Per ISOS consensus [Khenkin et al., 2020]:

  • Report forward and reverse scan parameters (Voc, Jsc, FF, PCE) for both directions
  • Report scan rate (mV/s), pre-bias conditions, and HI
  • Complement with stabilized PCE (MPP tracking or Stabilized Current ≥60 s)

35. Troubleshooting

❌ "No instruments found" in the connection dialog
Causes: KUSB-488B not detected; NI-VISA not installed; KI-488 in wrong mode; incorrect installation order.
Solutions:
  1. Check Device Manager for the KUSB-488B. A yellow exclamation mark indicates a driver problem.
  2. Open NI MAX — VISA resources should appear under Devices and Interfaces.
  3. If uncertain, repeat the full driver installation in Section 3 (clean → KI-488 in NI-compatible mode → NI-VISA → reboot → connect).
  4. Try a different USB port directly on the motherboard (avoid hubs).
❌ "ERROR ID CODE +803" on Keithley front panel
Cause: A measurement command was sent before :OUTP ON; usually from a partially-initialised state after a Python crash.
Solution: Press LOCAL on the Keithley. Turn output OFF. In software: Instrument → Disconnect, then reconnect. The *RST sent at the start of each measurement prevents this from persisting.
❌ "No current zero-crossing found" error
Causes: End Voltage is set below Voc; shutter is closed; cell is not illuminated or not connected.
Solutions:
  • Increase End Voltage to at least 0.1 V above the expected Voc.
  • Verify the solar simulator shutter is open and illumination is ≥100 mW/cm². If the software controls your shutter, see Section 10 — enabling Confirm the light state with an SMU reading catches this case before the data is saved.
  • Check cell contact polarity (Force HI to counter-electrode).
❌ Rsh very low (<100 Ω·cm²)
Causes: Pinholes or cracks in perovskite layer; incorrect cell area (too large).
Diagnostics:
  1. Verify the cell area value.
  2. Perform a dark J-V scan — a shunted cell will show significant current at V = 0.
  3. Inspect the cell optically for pinholes.
❌ S-shaped J-V curve (kink below Voc)
Cause: Extraction barrier at perovskite/transport layer interface; energy level misalignment; poor ETL quality.
Solutions:
  • TiO₂ ETL: UV-ozone treatment 15–20 min before perovskite deposition.
  • Spiro-OMeTAD HTL: verify doping concentrations (LiTFSI, Co complex).
  • Test a known-good reference cell to confirm the issue is the device, not the system.
❌ Pure MPP Tracking shows unstable or oscillating PCE
Causes: Perturbation step too large relative to the width of the MPP region; step interval too short (current not settled before next perturbation); high ionic noise in the cell.
Solutions:
  • Reduce the perturbation step to 0.005–0.010 V.
  • Increase the step interval to 500–1000 ms for ionic-active cells.
  • Run an initial J-V scan at a slow scan rate to verify the MPP region is well-defined before starting P&O tracking.
❌ Data Viewer shows blank plot or error opening a file
Causes: File saved by a version of the software before the current export format; mplcursors not installed.
Solutions:
  • The Data Viewer supports both new and legacy formats — check the terminal for the specific error message to identify the mismatch.
  • Install mplcursors: pip install mplcursors in the correct Python environment.
  • Verify the file is a valid .xlsx file with one of the supported sheet names (see Section 26).
❌ Software crashes or freezes on "Start Measurement"
Causes: GPIB timeout; instrument in unexpected state; Python package version incompatibility.
Solutions:
  1. Run from terminal (python main.py) to see the full Python traceback.
  2. Check PyVISA version: pip show pyvisa — should be ≥ 1.12.
  3. Verify GPIB address on the Keithley front panel matches the VISA resource address.
  4. Use Instrument → Disconnect and reconnect to reset the session.
